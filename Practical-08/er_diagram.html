Relationship & Integrity Explanations

  • Many-to-Many Relationship: A student can register for multiple events, and an event can be attended by multiple students. The registrations table resolves this M:N relationship into two 1:N relationships.
  • Composite Unique Constraint: UNIQUE(student_id, event_id) prevents a student from accidentally enrolling for the same event twice.
  • Referential Integrity: Foreign keys use ON DELETE CASCADE ON UPDATE CASCADE so that removing a student or event cleanly removes linked registration records.
